Method

AI does the reading. Deterministic checks and a senior engineer decide what ships.

Everything we deliver rests on one asset and one discipline: a fact graph extracted from your code, and gates that refuse to ship anything the graph can't back up.

The asset

The codebase fact graph

Every engagement builds and maintains a structured store of verified facts about your system - and every deliverable is a view over it.

The graph holds your modules, files, symbols, endpoints, data entities, dependencies, tests, code owners, documented claims, and captured knowledge. Every fact carries its evidence (paths, line ranges, commits), its extraction date, and its verification status.

  • The Control Score is metrics computed over the graph.
  • The Atlas Pack is documents rendered from it.
  • Capture adds human knowledge to it, attributed and dated.
  • Shield targets are graph queries: hotspots with no protection.
  • Evolve plans changes from the graph's computed impact sets.
  • Tower diffs graph snapshots over time - drift is a graph delta.

Because everything reads from the same verified source, your documentation, your tests, and your reports can never quietly disagree with each other - or with the code.

# one fact among thousands
fact: module "billing" calls module "notifications"
evidence: src/billing/invoice.py:214 -> notify_customer()
extracted: 2026-08-12, pipeline v1.4
status: verified (symbol + path check passed)

Facts, not source code, are what we retain. Your code is processed ephemerally and never stored.

The discipline

Six gates every deliverable must pass

These run automatically, before human review. Failing any of them blocks delivery - and the first one is backed by a refund.

GATE 01 · EVIDENCE

Every claim is checked against your code

Every file path and symbol cited in a deliverable must exist in your repository; a sample of causal claims ("X calls Y", "X stores Y") is audited against the actual source. The verification report ships with the deliverable. If it fails, you don't pay.

GATE 02 · REPRODUCIBILITY

Scores are deterministic

Control Score numbers come from pure analysis of your repo and git history. Same commit in, same numbers out - anyone on your team can rerun and confirm them.

GATE 03 · MUTATION

Tests must prove they can fail

Before a Shield ships, we plant controlled mutations in your code and verify the new tests turn red. The mutation report is part of the delivery: you see the suite catching real changes.

GATE 04 · ATTRIBUTION

Knowledge is attributed, never laundered

Captured knowledge carries who said it and when, and whether the code corroborates it. Statements the code contradicts go back to the expert - never silently kept, never silently dropped.

GATE 05 · NO SILENT CHANGE

Behavior changes only through signed tickets

During Evolve, CI blocks any modification to a pinned behavior that doesn't reference a ticket you signed. Everything outside the tickets is machine-verified unchanged.

GATE 06 · ACCEPTANCE FIRST

The test exists before the code changes

Every behavior change starts with its acceptance test, written and recorded failing on the current system. Work is done when that test is green and everything else still is.

Working together

How an engagement runs

  1. Intake and feasibility

    A short call, NDA if you want one, read-only access set up your way. We run a feasibility check first - if your stack or repo isn't a good fit for our pipelines, we tell you before any money changes hands.

  2. Control Score in 48 hours

    The audit runs, the report lands, and we walk through it together. You now hold the measured picture and a priced 90-day plan. Many clients stop here; the report is yours either way.

  3. You choose the path

    Pick the offerings the plan recommends, in the order that matches your risk and budget. Fixed prices are committed in writing before each phase starts.

  4. Delivery in reviewable increments

    Everything arrives as documents and pull requests your team reviews - weekly, not as a big bang. Our pipelines do the volume; a senior engineer signs every delivery; the gates run on all of it.

  5. Control stays with you

    Deliverables, the fact graph, tests, and reports are yours, in your repositories, in standard formats. If we disappear tomorrow, everything keeps working. Tower is how control persists - not lock-in.

Security & data

Built for companies that are careful with their code.

    On request, the pipelines execute in your CI or on your infrastructure, and nothing leaves your network at all.

    Read-only access is all recovery work needs. Write access is scoped to pull requests only, on the repositories you designate, revocable by you at any moment.
