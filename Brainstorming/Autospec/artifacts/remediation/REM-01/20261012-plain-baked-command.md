# Exact reviewed command baked into the final image

Counter-review established that final-image qualification could override its
CMD with the source-reviewed launcher: e.g. a FastAPI module without a
`__main__` launcher would serve via injected `python -m uvicorn` while the
delivered image's default `python main.py` did not serve anything.

`build_delivery_image(...,runtime_command=list(exact_reviewed_argv))` now bakes
that explicit factory command and records `runtime_command` and
`runtime_command_mode=explicit-factory`. The absent parameter preserves only
legacy construction compatibility (`legacy-default`); production OPS admission
must reject that mode. Source/binding review remains the caller's authority,
not a claim generated by accepting an argv parameter.

The factory recipe resets `ENTRYPOINT []`, writes JSON CMD and inspects the
actual immutable image ID/Cmd/entrypoint/snapshot label after build. Node ESM
finds its locked immutable dependencies via a factory-owned global
`/node_modules -> /opt/node_modules` link, not a source overlay. The only root
build action is the constant link creation, before returning to USER65532;
the final builder is NETNONE and executes no product script/Dockerfile.

`RuntimeSession(...,mount_stage=False,use_image_command=True)` requires an
immutable image, attests the exact reviewed argv equals Config.Cmd and that no
entrypoint exists before even creating a DB volume, then runs the bare image:
no `--entrypoint`, argv override, Node wrapper or host source bind. It rechecks
on each launch/restart. `OwnedProductHarnessSession(image_id=...)` always uses
this flag. Command mismatch is unavailable, never corrected by an overlay.
Runtime inspection also exposes its actual container command/entrypoint.

Native proof: **10 PASS/14.61s**, including two actual final-image builds and
bare launches under Linux NETNONE/read-only/non-root. Python FastAPI main:app
without `__main__` starts via its baked uvicorn CMD; Node ESM imports the actual
locked React19.0.0 dependency without a RuntimeSession wrapper. Divergent host
stage source is ignored, actual container Cmd/entrypoint/mounts are inspected,
and a different expected argv is refused before launch. Unit cases additionally
reject inherited shell entrypoint, source mount with plain-image mode and
unbounded/invalid commands. No hostile or generated code ran on Windows and no
paid model/API call was made. These fixtures prove entrypoint/isolation ports,
not the support product's complete 57-criterion acceptance.

Initial combined replay: 33 PASS/2 FAIL in121.05s, preserved. Docker29.5.3 omits
the JSON Entrypoint key for actual empty ENTRYPOINT; absence is therefore
accepted, while any nonempty entrypoint remains refused. Node's non-root base
initially denied the factory global-link creation; the explicit root constant
step corrected it. The v2 JUnit contains the final ten-case pass.

Parent raccord requires binding.validate(source), exact snapshot/contract,
after final independent source review, before passing argv to the builder.
The delivery-evidence owner separately verifies the exact recipe/CMD against
current Docker inspect and rejects legacy-default. No task closes before those
raccords and global regression are integrated/counter-reviewed.
