# Couverture Node confinée et liée aux sources — 2026-10-12

Port `IsolatedValidator.run_suite(root, 'node', 'test', reportpath, coveragepath=supervisorpath, coverage_source='src')`. L'environnement Linux propre doit déclarer/verrouiller exactement `vitest==2.1.9` et `@vitest/coverage-v8==2.1.9` via le coordinateur. Absence, mismatch, runner non qualifié : refus, aucune installation implicite par Vitest et aucun fallback hôte. D'autres versions/providers ne sont pas qualifiés par cette preuve.

Recette factory : Vitest direct, aucun npm script; V8/all/include/exclude imposés par CLI. Le JSON Istanbul `coverage-final.json` vient d'un répertoire `/tmp/autospec-coverage-<UUID>` neuf hors code produit, export limité au fichier régulier attendu. Rapport de suite séparé, source/caches produit filtrés, réseau none/nonroot/capsdrop. Le rapport caché du producteur ne peut pas servir de preuve fraîche.

Sortie persistée/retournée : `{format:'istanbul-executable-lines-branch-arms', files:{relative:{summary:{covered_lines,num_statements,missing_lines,num_branches,covered_branches},executed_lines,missing_lines}}, totals:{mêmes compteurs,percent_covered}, autospec_inventory:{version,source,files:SHA256,source_fingerprint,environment_fingerprint,image}}`. `num_statements` compte ici les lignes exécutables distinctes; les branches sont les bras Istanbul. Les totaux sont recalculés exclusivement sur l'inventaire source pré-exécution. Tests/config/declarations sont exclus; tout fichier inventorié absent, count négatif/bool, map incomplète ou ligne hors source invalide la couverture et `report_valid`. Le pourcentage combine lignes et branches comme le port Python; le collecteur peut calculer séparément le taux de lignes depuis les compteurs explicites.

Preuve Windows -> Docker Linux, sans exécution source/Node/npm sur l'hôte : `AUTOSPEC_REAL_LINUX_VALIDATION=1 pytest tests/test_node_coverage_isolated.py tests/test_captured_and_baked_validation.py tests/test_linux_validation.py -q -k 'node_coverage or istanbul or coverage_requires or captured_never'` : **12 PASS, 16 deselected / 31.08s**. La fixture réelle couvre deux branches business, garde un module jamais importé à zéro malgré config produit `all:false` et exclusion de ce module, rejette le faux rapport à 100% présent dans le produit. Aucun node_modules hôte créé. Premier essai : 9 PASS/1 FAIL sur assertion d'un compteur `executed` optionnel du parseur Vitest; corrigée en vérification du test collecté et de son outcome réel, aucun défaut de couverture masqué.

Documentation primaire version qualifiée : [Vitest v2 coverage](https://v2.vitest.dev/guide/coverage), [Vitest v2 config coverage](https://v2.vitest.dev/config/). `coverage.all`, include/exclude CLI et reporter JSON sont ceux de cette version, pas une hypothèse sur la version latest.

Limite : la couverture native n'est pas seule une preuve métier; les contrôles d'intégrité et l'oracle indépendant restent obligatoires. Le budget/API de Claude n'a pas été appelé. Ce port ne ferme REM19 qu'après raccord du collecteur et contre-revue du parent.
